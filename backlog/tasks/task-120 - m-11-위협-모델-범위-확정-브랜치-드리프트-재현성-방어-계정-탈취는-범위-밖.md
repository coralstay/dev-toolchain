## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
2026-08-30 논의 결과 기록. m-11(다운로드/설치 체인 무결성 검증)이 성립하는 근거: 이 저장소는 실제로 public이며(2026-08-28 rescope 논의 후 유지 결정), curl|sh 진입점 자체가 메인테이너 외 타인이 실행할 수 있음을 전제로 함. 개인용 전용 스크립트였다면 m-11의 우선순위는 훨씬 낮았을 것.

self-clone pinning(TASK-117.1)의 스코프 경계 — 방어하는 것: 의도치 않은 브랜치 드리프트(실수로 잘못된 커밋이 force-push된 순간 curl|sh가 실행되는 경우), 제한된 권한의 토큰/자격증명 유출(계정 전체가 아니라 push 권한만 새는 경우), 재현성·감사 가능성(버그 리포트 시 "그 시점 정확히 어떤 커밋이었는지" 추적).

방어하지 않는 것 (명시적으로 스코프 밖): GitHub 저장소/계정 전체 탈취. 이 경우 공격자는 install.sh 안에 박힌 고정 커밋 SHA 자체도 함께 바꿀 수 있어 self-referential pinning으로 막을 수 없음 — 이건 GitHub 쪽 계정 레벨 통제(브랜치 보호 규칙, 서명된 커밋 요구, 2FA)의 영역이며 셸 설치 스크립트가 풀 수 있는 문제가 아님. TASK-117.1/117.4 구현 시 이 경계를 넘어서는 "완전한 tamper-proof"를 목표로 삼지 않는다.
<!-- SECTION:DESCRIPTION:END -->
